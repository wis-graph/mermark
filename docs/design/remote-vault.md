# 원격 볼트 — mermark ↔ mermark 읽기 전용 연동 설계

- 상태: 설계 확정 (구현 계획 대기)
- 작성: 2026-09-14
- 범위: v1 = 읽기 전용

## 1. 문제

맥미니에 있는 볼트를 맥북의 mermark에서 그대로 열람하고 싶다. 지금은
터미널로 SSH 터널을 직접 뚫어야 하고, 그건 만든 사람만 쓸 수 있는 방법이다.
mermark 사용자 누구나 "호스트 이름 + 코드" 두 줄로 붙을 수 있어야 한다.

## 2. 확정된 결정

| 항목 | 결정 | 근거 |
|------|------|------|
| 방향 | 밖(맥북) → 안(맥미니) 열람 | 클라이언트는 브라우저가 아니라 맥북의 mermark 앱 |
| v1 쓰기 | 읽기 전용 | 네트워크 너머 충돌가드·워처·저장실패 복구를 전부 회피해 v1을 절반으로 |
| 전송 | Tailscale 우선, SSH 터널 폴백 | 테일넷이 이미 암호화·인증·NAT 통과를 제공 |
| 마운트(SMB/sshfs) 방식 | 기각 | 끊김 시 커널 블로킹으로 UI가 통째로 얼어붙고 타임아웃 수단이 없음 |
| 헤드리스+브라우저 | 이번 범위 아님 | 요구는 맥북 mermark 앱이 클라이언트인 것. 서버는 나중에 재활용 가능 |
| 캐시 | 넣지 않음 | 무효화·용량·스테일 표시를 끌고 들어오는데 온라인 상황이 대부분 |

## 3. 의존성 실측

- `tokio`·`hyper`·`reqwest`가 이미 빌드 그래프에 있다(`tauri-plugin-updater` 경유).
  → **클라이언트 측 새 크레이트 0개.**
- 서버 측만 `axum` 1개 추가.
- 프론트엔드가 HTTP를 직접 말하지 않고 Rust를 경유하므로
  `tauri.conf.json`의 CSP `connect-src`는 **변경 없음**.
- mermark는 App Sandbox를 쓰지 않으므로 incoming 서버용 엔타이틀먼트(entitlement) 불필요.
  단 macOS 방화벽이 첫 바인드에 승인 팝업을 띄운다 → 페어링 안내에 포함.

## 4. 아키텍처

기존 보안 관용구(`htmlview.rs`/`epubview.rs`)를 그대로 따른다. 새 패턴을
발명하지 않는다: 128비트 CSPRNG 토큰(`mint_view_token`) + armed root +
`is_within_armed_root` 동형의 봉쇄 검사.

### 4.1 호스트 측 — `src-tauri/src/remote_host.rs` (신규)

- axum 서버. 바인드 대상은 설정값: Tailscale 인터페이스 또는 `127.0.0.1`.
  포트 기본 8787.
- 공유 대상은 사용자가 설정에서 체크한 **볼트 단위 armed root 목록**.
  홈 전체가 아니다. 체크된 게 없으면 아무것도 열리지 않는다.
- 모든 경로 요청은 봉쇄 검사를 통과해야 한다: `..`, 절대경로, 심볼릭 링크 탈출 차단.
- **기본 꺼짐.** 사용자가 명시적으로 켜야 열린다.
- 파일 로직은 `commands.rs`의 기존 함수를 그대로 호출한다. 서버는 HTTP 껍데기 +
  봉쇄 검사만 담당 → 파일 로직 한 벌 유지.
- **읽기 전용은 라우트 부재로 구현한다.** 클라이언트가 착해서가 아니라
  파일 쓰기 엔드포인트가 존재하지 않아서 못 쓴다.
- 예외는 페어링 교환(`POST /pair`) 하나뿐이다. 이것은 파일을 건드리지 않고
  토큰만 발급하며, 파일 라우트(`/vaults`, `/list_dir`, `/read_file`,
  `/resolve_image`, `/list_link_targets`)는 전부 `GET`만 받는다.

### 4.2 클라이언트 측 — `src-tauri/src/remote_client.rs` (신규)

- `reqwest`로 호스트 호출. **모든 호출에 명시적 타임아웃**(연결 3초 / 응답 10초).
- 프론트엔드에는 기존과 동형의 `#[tauri::command]` 표면으로 노출:
  `remote_list_dir`, `remote_list_files_recursive`, `remote_read_file`,
  `remote_resolve_image`, `remote_list_link_targets`, `remote_path_exists`.

### 4.3 프론트엔드 초크포인트 — `src/document/file-host.ts` (신규)

현재 파일 접근에 단일 출처가 없다 — `invoke<>()` 40곳이 29개 파일에 흩어져 있고,
그중 읽기 경로는 약 15곳이다. 이 15곳이 `file-host.ts`를 거치게 바꾼다.

- 볼트의 `persistenceKind`로 분기: `permanent`/`global` → 기존 로컬 커맨드,
  `remote` → 원격 커맨드.
- 이 정리는 원격 기능이 없어도 그 자체로 가치가 있다.

### 4.4 볼트 모델 — `src/workspace/workspace-state.ts` (확장)

`PersistenceKind`에 `"remote"`를 추가하고 `RemoteVault`를 정의한다:
`rootPath: null`, 대신 `host`(테일넷 이름 또는 `ssh://user@host`),
`remoteVaultId`, 기기 토큰 참조.

### 4.5 데이터 흐름

```
맥북 mermark UI
  └ file-host.ts  (볼트 종류로 분기)
      └ invoke("remote_list_dir", { host, vaultId, path })
          └ remote_client.rs ── reqwest(타임아웃) ──┐
                                                    │ Tailscale (WireGuard)
맥미니 mermark                                       │
  └ remote_host.rs  axum ◄──────────────────────────┘
      ├ 토큰 검증 (상수시간 비교)
      ├ armed root 봉쇄 검사
      └ commands.rs 기존 함수 재사용
```

## 5. 인증과 페어링

"다른 사용자도 간편하게"가 사실상 이 절 하나에 걸려 있다.

**호스트(설정 › 원격 공유)**
1. `공유 켜기` 토글 (기본 꺼짐)
2. 공유할 볼트 체크박스 선택 = armed root 목록
3. 바인드 방식: Tailscale(감지 시 기본) / 로컬호스트만(SSH 터널용)
4. **6자리 페어링 코드** 표시 + 5분 카운트다운

**클라이언트(볼트 추가 › 원격 볼트)**
1. 호스트 이름과 페어링 코드 입력.
   호스트는 `wis-macmini`처럼 이름만 적으면 기본 포트 8787을 쓰고,
   `wis-macmini:9000`처럼 포트를 붙이면 그쪽을 쓴다.
2. 공유된 볼트 목록에서 선택 → 사이드바에 추가

**2단계인 이유.** 6자리 코드는 사람이 불러줄 수 있지만 그만큼 약하다.
따라서 코드는 **5분 만료 + 1회용 + 시도 횟수 제한**이고, 교환의 결과로
클라이언트가 받는 것은 128비트 기기 토큰(`mint_view_token` 재사용)이다.
이후 모든 요청은 그 토큰으로 하며 비교는 상수시간.

**토큰 보관.** 프론트엔드 `localStorage`에 두지 않는다(웹뷰 스크립트에 노출).
Rust 측 앱 설정 디렉터리에 `0600`으로 저장한다. 정석은 macOS Keychain이지만
크레이트가 하나 더 붙고, 이 토큰의 권한이 "테일넷 안에서 공유된 볼트 읽기"로
한정돼 있어 v1에서는 파일 보관이 합당하다 — **의도적 트레이드오프이며
업그레이드 경로를 열어둔다.**

**철회.** 호스트 설정에 페어링된 기기 목록과 `연결 해제` 버튼. 발급만 하고
회수할 수 없으면 설계가 아니다.

**SSH 폴백.** Tailscale이 없으면 호스트를 `ssh://user@host`로 입력한다.
mermark가 `ssh -L 8787:localhost:8787 -N`을 자식 프로세스로 띄우고 그 위로 붙는다.
사용자가 보는 절차는 동일하다(호스트 + 코드). **mermark는 SSH 키를 다루지 않는다** —
사용자의 기존 SSH 설정을 그대로 쓴다.

## 6. 오프라인과 에러 처리

원칙: **조용한 강등 금지.**

- 모든 원격 호출에 명시적 타임아웃. 초과해도 UI는 살아 있다.
- 원격 볼트 행에 연결 상태 배지 **4종 구분**:
  `연결됨` / `연결 안 됨` / `인증 만료` / `호스트가 공유를 껐음`.
  하나로 뭉치면 사용자가 무엇을 고쳐야 할지 알 수 없다.
- 탐색기는 원격 디렉터리 로딩 중 스켈레톤 표시. 동기 블로킹 없음.
- 에디터는 원격 문서를 **읽기 전용 모드**로 열고 상태바에 명시한다.
  편집 시도가 조용히 무시되어서는 안 된다.
- 원격 볼트의 PDF·DOCX·XLSX/XLS/CSV·HTML(스크립트 실행 ON 포함)은 v1.1(0.18.0)부터
  **정상적으로 열린다** — `remote_read_asset`이 바이트를 실어 나르고, 뷰어 레지스트리의
  각 `Viewer`가 `openRemote(source)`를 선택적으로 구현해 스스로 원격 지원을 선언한다
  (손으로 유지하는 확장자 목록이 아니라 뷰어 자신의 선언 — 새 뷰어가 붙어도 드리프트 없음).
  남은 세 종류는 **각자 다른 이유로, 다른 문구로** 거절한다: SQLite는 "필요한 부분만
  디스크에서 읽어야 해서" 구조적으로 영구 미지원(「아직」을 쓰지 않는다 — 전체 전송이
  이 뷰어의 존재 이유를 깬다), EPUB은 Range 요청이 필요해서, HWP/HWPX는 원격 바이트를
  로컬 임시 파일로 내려야 하는 수명 부채 때문에 각각 이번 라운드는 범위 밖(영구 아님).
  깨진 뷰어를 띄우지 않는다는 원칙은 그대로 — 셋 다 명시적 거절 메시지를 낸다.
- **이미지는 바이트로 실어 나른다**(Ruling 7). `/resolve_image`는 경로만 돌려주는데
  원격 파일의 경로는 이쪽 디스크에 존재하지 않으므로, `convertFileSrc`로는 절대
  표시되지 않는다. `GET /read_asset`이 바이트를 주고 클라이언트가 `data:` URL로 만든다.
  CSP `img-src`에 이미 `data:`가 있어 보안 설정 변경은 없다.
- **원격 볼트에서는 자동 파일 생성 경로를 막는다**(Ruling 8). 없는 `[[링크]]` 클릭이
  `create_markdown_file`을 타면 엉뚱한 머신에 파일이 생긴다. v1 읽기 전용을 깨는 경로다.

## 7. 테스트 전략

**Rust (`cargo test`)**
- 봉쇄 검사 탈출 시도: `..` / 절대경로 / 심볼릭 링크 — `htmlview.rs`의 기존
  탈출 테스트를 본뜬다.
- 페어링 코드: 만료 후 거부, 재사용 거부, 시도 횟수 초과 거부.
- 토큰 비교가 상수시간인지.
- **파일 쓰기 라우트 부재 테스트**: 모든 파일 라우트가 `GET` 외의 메서드에
  405를 반환한다(`POST /pair`는 이 규칙의 유일한 예외이며 파일을 건드리지 않는다).
  읽기 전용을 주석이 아니라 테스트로 고정한다.
- 서버 왕복: 임시 디렉터리를 armed root로 띄우고 `list_dir`·`read_file` 실제 응답 검증.

**TypeScript (`vitest`)**
- `file-host.ts` 라우팅: 볼트 종류 → 올바른 커맨드. 초크포인트의 계약.
- 연결 상태 4종 → 배지 매핑.

**경계면 parity (프로젝트 상시 규약)**
- 새 커맨드를 `src/mocks/tauri-core.ts`에 동시 반영.
  Rust serde ⇄ TS `invoke<>` ⇄ 브라우저 mock 3중 정합.

**실앱 검증 (생략 불가)**
- 골든마스터는 http origin에서 돌아 실앱 전용 문제를 못 잡는다. 네트워크 바인드·
  방화벽 팝업·Tailscale 인터페이스 선택은 `tauri build` 번들로
  **맥미니↔맥북 실기 왕복**을 해야 확인된다. 릴리스 전 필수 게이트.

## 8. 비범위 (v1에서 하지 않는 것)

- 원격 문서 편집·저장
- 오프라인 캐시
- 원격 볼트의 EPUB/HWP 뷰어 (이번 라운드는 범위 밖 — 영구 아님, §6 참조)
- 원격 볼트의 SQLite 뷰어 (구조적으로 영구 미지원 — §6 참조. PDF/DOCX/XLSX/HTML은
  0.18.0부터 원격에서 열린다 — 더 이상 비범위가 아니다)
- 브라우저·모바일 클라이언트 (서버는 나중에 재활용 가능)
- Tailscale API를 통한 기기 자동 발견 (호스트 이름 수동 입력으로 충분)
- macOS Keychain 토큰 보관 (§5 트레이드오프 참조)
