# mermark 기능 계층 문서

> mermark의 전체 기능을 아키텍처 계층별로 구조화한 단일 참조. **기능을 추가/변경하면 이 문서를 갱신한다**(mermark-dev 파이프라인 Phase 6 규약). 정체성: 가벼운 마크다운 파일 편집·렌더링을 중심으로, 선택 가능한 workspace/vault 탐색과 탭을 제공하는 경량 에디터.
>
> 기준 버전: v0.15.0 (`package.json`, 배포됨) + 미배포 변경분(블록 기하 테마화) · 최종 갱신: 2026-08-21

## L1 · 백엔드 계층 (Rust / Tauri)

### 1.1 파일 IO
- **read_file / write_file** — 원자적 쓰기(temp + rename)로 부분 저장 손상 방지.
- **conflict guard** — read 시 mtime baseline 기록 → write 시 디스크 변경 감지(`CONFLICT:`), `.mermark-recovered` 복구.
- **fs 와처** — `notify` 크레이트로 **열린 파일 1개만** watch(`watch_file`/`unwatch_file`, 경로 전환 시 슬롯 교체). 외부 변경 시 `file-changed` 이벤트(`{text,mtime}`) emit. 자기 쓰기 self-trigger 방지(mtime baseline `record_self_write`/`is_self_write`).
- **path_exists** — 위키링크 대상 존재 확인.
- **list_dir** — 한 디렉토리 레벨을 `Vec<DirEntry>`(`{name, path, is_dir}`)로 반환하는 레이지 리스팅. 폴더 먼저·이름순 정렬, read-only. 제외 규칙은 두 갈래: 아티팩트(`is_mermark_artifact`)는 **항상** 제외, 숨김(`.` 시작)은 `show_hidden` 인자로 **조건부** 제외(기본 제외 — L2 §2.3 "숨김 파일 표시 토글"이 인자를 준다). 없는/막힌 폴더는 graceful `Err`(빈 폴더는 `[]`). 파일 탐색기가 폴더 클릭마다 한 레벨씩 호출.
- **resolve_image** — 리터럴 경로에서 못 찾은 이미지를 baseDir 가두리(≤3 depth) 안에서 read-only 재귀 스캔해 basename 일치 파일의 절대경로를 반환(`Option<String>`). 경로 탈출/심링크 가드, 확장자 화이트리스트, 깊이·엔트리 상한. 못 찾으면 `None`(graceful).
- **경로 정규화** — `normalize_path`(`..` collapse) + `expand_home`(선두 `~`/`~/` 홈 확장, `~user` 과확장 금지).
- **list_files_recursive** (신규, `⌘⇧F` 파일 찾기 패널 전용) — `root` 아래를 재귀 walk해 `ScanResult{files: FileHit[]{name, path, rel_path}, truncated}`로 반환. `MAX_SCAN_DEPTH=12`·`MAX_SCAN_FILES=10_000` 상한(초과 시 `truncated:true`, 부분 리스팅임을 정직하게 신고), `node_modules`/`.git`/`target`/`dist`/`build`/`__pycache__`/`.venv`는 무조건 제외. `show_hidden`은 `list_dir`과 동일 계약(§2.3 숨김 파일 토글 값을 그대로 받음). 디렉토리 심링크는 절대 미추종(탈출 방지), 파일 심링크는 `list_dir`과 같은 관례로 그대로 나열. 읽기 전용 — conflict guard 미해당, 신규 write 경로 0.
- **hwp_open / hwp_render_page / hwp_close** (`src-tauri/src/hwp.rs`, 신규) — 고정 rev `rhwp` 크레이트로 HWP/HWPX를 파싱·페이지 단위 SVG 렌더. 단일 슬롯 세션(`Mutex<Option<HwpSession>>`, 파싱 1회 후 페이지는 세션 재사용, `hwp_open`이 기존 세션 교체). 읽기 전용(쓰기 0, conflict guard 미해당). 방어: 파일 크기 상한 100MB(read 전 거부), 파싱 30s/렌더 10s 타임아웃, `catch_unwind`로 파서/렌더러 패닉을 `Err`로 봉쇄(손상 파일이 프로세스를 절대 죽이지 않는다 — 잔여 리스크는 스택오버플로 abort, 문서화하고 수용). 플랫폼별 한글 폴백 폰트 오버라이드(`platform_fallback_font`). CSP/capabilities/`read_file`·`write_file` 시그니처 전부 무변경.

### 1.2 CLI / 창
- **단일파일 열기** — CLI 인자로 파일 1개를 즉시 여는 빠른 진입 경로다. `cli.rs`엔 확장자 게이트가 없어 어떤 경로든 그대로 넘어가고, **무엇으로 열지는 프론트가 뷰어 레지스트리로 판정한다**(2026-08-19): 등록된 뷰어가 claim하는 확장자면 뷰어로, 아니면 문서로 연다 — 즉 `mermark foo.pdf`/`foo.epub`/`foo.png`가 터미널에서 열린다. 이전엔 CLI만 이 판정을 건너뛰고 무조건 문서로 읽어 `stream did not contain valid UTF-8`로 실패했다(같은 파일을 탐색기에서 클릭하면 정상이었다). 문서로 열릴 때, 그 경로가 `.txt`이면 에디터 안에서 `.md`와 **완전히 동일하게** 렌더된다(같은 라이브프리뷰 파이프라인, 플레인텍스트 분기 없음) — 탐색기/검색/위키링크가 `.txt`를 md와 같이 취급하도록 확장된 것과 짝을 이룬다. 꺼둔 뷰어의 확장자는 앱 내부 클릭과 동일하게 OS 기본 앱(`open_path`)으로 폴백한다.
- **없는 경로는 오류** (2026-08-19, 이전 동작 폐기) — `mermark 없는파일.md`는 예전엔 vim `:e newfile` 관례로 그 파일을 **새로 만들었다**(`# {제목}` 헤더까지 써서). mermark의 주 기능이 뷰어이므로 이 편의는 폐기됐다: 이제 존재하지 않는 경로는 디렉터리 인자와 **똑같은 방식**으로 거부된다 — 터미널에 `mermark: {경로} does not exist.` + `usage: mermark <file>`을 찍고 exit(2), 창은 뜨지 않는다. 이 판정은 `tauri::Builder`와 싱글턴 인스턴스 플러그인이 생기기 **전**에 일어나므로, 다른 mermark 창이 이미 떠 있어도 잘못된 경로가 그 창으로 조용히 전달되지 않고 터미널을 쥔 프로세스가 즉시 피드백을 받는다. 위키링크로 새 문서를 만드는 기능(`create_markdown_file`)은 그대로다 — 없어진 건 "런치 시 없는 타겟을 낳는다"는 규칙 하나뿐이다.
- **단일 창 CLI 라우팅** (신규, single-window-opening) — 평범한 `mermark <file>` 실행이 2차 프로세스일 때, Tauri 공식 싱글턴 인스턴스 플러그인이 그 launch를 가로채 **마지막으로 포커스된 살아있는 mermark 창**에 전달한다(`cli-open-request`/`acknowledge_open_request` 브로커, 창별 `register_window_ready` 이후에만 수신 시작). 그 창이 없으면 살아있는 `main`, `main`도 없으면 `main`을 재생성해서 연다 — 임의의 `w*` 창으로 폴백하는 경우는 없다(`resolve_recipient` 진리표가 단일 출처). 창이 아직 준비되지 않은 시점에 도착한 요청은 큐잉되고, 열기 성공 또는 (충돌/오류로 인한) 가시적 복구 상태 둘 중 하나로 반드시 ack된다 — 조용히 사라지는 요청은 없다. `-`(stdin 파이프)와 `--right`는 이 가로채기 대상이 **아닌 격리 실행**이라 항상 독립 프로세스·독립 창으로 뜬다(아래).
- **누락 파일 자동 생성** — 없는 경로 인자 시 Vim식 생성.
- **`--right`** — 창을 화면 우측 절반에 배치. 싱글턴 라우팅 대상이 아닌 격리 실행(위).
- **`-v` / `--version`** — 현재 버전(`mermark 0.10.1`)을 출력하고 즉시 종료. `lib.rs run()`에서 창 생성 전 헤드리스로 short-circuit(`cli::is_version_flag` 순수 판정 → `CARGO_PKG_VERSION` 단일 출처). `-v`는 단일 대시라 파일 인자로 오인되지 않도록, `--version`은 무시되는 미지 플래그에 섞이지 않도록 `parse_args` 앞에서 가로챈다. mac/Linux 터미널(설치된 CLI 래퍼)에서만 콘솔에 보임 — bundle 서브커맨드와 같은 한계.
- **bundle CLI / `bundle_doc`** — 위키링크 추종해 문서를 LLM 컨텍스트로 패키징(부모/절대 경로 포함).
- **명시적 새 창 열기 (`open_path`)** — 탐색기·파일 찾기의 ⌘/Ctrl+클릭 또는 ⌘Enter**만**이 새 창(`w*`)을 스폰한다(불변, 계속 유지됨). 위키링크·표준 로컬 링크·경로열기·최근 문서·즐겨찾기·CLI 라우팅(위) 등 그 외 모든 문서 열기 경로는 전부 **현재 창**의 안전 트랜잭션(`openDocumentSafely`)을 공유한다 — "새 창"은 이 두 명시적 제스처와 `-`/`--right` 격리 실행 전용이다.

### 1.3 보안 설정
- **CSP** — `img-src`/`font-src`(asset:·data:·https:), `media-src`(로컬 비디오), `frame-src`(youtube-nocookie/youtube), `connect-src`(ipc:·asset:), `object-src 'none'`.
- **assetProtocol scope** — `["**"]` + `requireLiteralLeadingDot:false`(숨김폴더 이미지 로드).
- **capabilities** — 최소 권한 셋.

## L2 · 프론트 인프라 계층 (CodeMirror 6 / TypeScript)

### 2.1 라이브프리뷰 파이프라인
- **플러그인 레지스트리** — 기능별 모듈(`InlineFeature` / `BlockFeature`) 등록 구조.
- **conceal / reveal** — 마크다운 마커를 숨기고(conceal) 캐럿이 줄에 들어오면 원문 노출(reveal). core `revealed()`가 단독 소유.
- **데코 경로 분리** — 인라인=ViewPlugin, 블록 위젯=StateField(render-smoke 불변식).
- **블록 진입** — 키보드(기하 모션)·클릭(`clickEntry`)으로 블록 위젯 안으로.

### 2.2 에디터 상태
- **세션 영속** — 파일별 scroll/cursor 위치 저장·복원.
- **모드 / Vim compartment** — 런타임 재구성(edit↔read, vim on/off).
- **drawSelection** — EditorState 셀렉션 레이어(Vim 비주얼·멀티커서 가시화, `--selection-bg` 토큰).
- **경로 열기 re-point** — `openInWindow` + `current` SSOT로 새 파일을 현재 창에 재마운트(baseDir/filePath/autosave/세션 전수 갱신).
- **저장/리로드 자동화** — 자동저장(타이핑 멈춤 200ms debounce, 수동 저장 버튼 없음). 외부 변경 감지 시 미저장 없으면 자동 리로드, **충돌(미저장+외부변경)이면 VSCode식 diff 모달**(라인 LCS, 로컬 유지 / 외부 채택 선택). 저장 상태 인디케이터로 신호.

### 2.3 워크스페이스·볼트·탭
- **workspace/vault 상태** — `WorkspaceStore`가 workspace와 영구 볼트, 현재 선택 볼트, 볼트별 탐색기 루트를 관리하고 localStorage에 영속화한다. 글로벌 볼트는 파일 인자나 명시적 루트가 없는 세션의 안전한 기본값이다.
- **볼트 사이드바** — `workspace-sidebar.ts`가 볼트 선택·영구 볼트 해제·탭 스트립을 제공한다. 파일 트리는 `ExplorerPanel`의 레이지 디렉터리 목록으로, 빈 폴더·오류·재시도·새로고침·제한 결과를 구분한다. **볼트 이름 클릭은 항상 그 볼트의 탐색기를 연다**(루트=그 볼트 루트 — 이전엔 열 문서가 없을 때만 열렸다, `main.ts`의 `onSelectVault`가 문서 열기/웰컴 두 경로 모두에서 `explorer.jumpToRoot`를 무조건 호출; `jumpToRoot`의 `revealShell`이 패널 레지스트리를 거치므로 워크스페이스 패널은 상호배제로 닫힌다). **볼트 접기/펼치기**(신규) — 각 볼트 행의 폴더 글리프 자체가 토글이다(펼침 `folder-open`/접힘 `folder`, `aria-expanded` 동기, `renderVaultCollapse` 단일 지점) — 이름(`select`) 클릭은 진입, 글리프(`toggle`) 클릭은 접기/펼치기로 히트 타깃이 분리된다. 이 글리프는 더 이상 글로벌 볼트를 뜻하지 않는다 — 그 구분은 "영구 볼트" 그룹 라벨이 전담한다. 접힘 상태는 볼트별로 `vault-collapse.ts`의 `mermark.vaultCollapsed.<vaultId>`에 영속(기본 펼침, 접힘일 때만 키를 쓴다). **탭 우물** — 각 볼트의 탭 스트립이 `--sidebar-well`(`--sidebar-fg` 5% color-mix 파생) 면 위에 담겨 부모-자식 구조가 보인다; 탭 폰트도 10px→12px(`calc(12em/13)`)로 커졌고, 텍스트는 3단 스케일을 따른다(볼트명·활성 볼트의 활성 탭 = `--sidebar-fg` > 그 외 탭 파일명 = `--sidebar-fg-soft`(`--sidebar-fg` 65% + `--sidebar-muted` color-mix 파생) > 접두사·그룹 라벨 = `--sidebar-muted`) — 두 신규 토큰 모두 기존 토큰의 파생값이라 3테마+커스텀 테마를 자동 추종한다. **호버 시에만 나타나는 액션** — 탭 닫기(×)와 볼트 해제(북마크)는 평소 `opacity:0`, 행 hover 또는 `:focus-within`에서만 노출된다; 히트 타깃 자리는 항상 예약돼 있어 노출 시 파일명 말줄임 위치가 튀지 않는다. **활성 표현** — 활성 볼트는 행 전체가 accent 배경 + 좌측 인셋 바를 두르고 그 안의 활성 탭은 같은 accent 언어(배경+좌측 바)를 이어받지만, 비활성 볼트의 활성 탭은 색만 바뀌는 약한 "돌아올 자리" 표식이라 여러 볼트가 동시에 열려 있어도 진짜 현재 위치가 한눈에 갈린다. **탭 아이콘/라벨/정렬**(신규) — 탭도 `renderEntryGlyph`의 세 번째 소비자다(탐색기·파일 찾기와 같은 Material 아이콘을 그대로 공유). 아이콘이 타입을 말하므로 라벨에서 확장자를 뗀다(`extensionOf`가 빈 문자열이 아닐 때만 — `README`·`.gitignore`처럼 확장자 없는 이름은 그대로 유지), 전체 경로는 `title` 툴팁에 남는다. **상위 폴더 접두사**(`folderPrefixFor`) — 볼트 루트 직속 파일은 접두사 없음, 2단계 이상 깊으면 `…/`만, 1단계는 10자(`MAX_PREFIX_CHARS`) 초과 시 잘라 `…/`로 표시, 글로벌 볼트처럼 `rootPath`가 없으면 접두사 자체가 없다; 바로 위 줄과 같은 폴더면 생략하되 그 판정은 표시 문자열(둘 다 `…/`일 수 있는)이 아니라 실제 `dirOf` 경로로 비교해 서로 다른 깊은 폴더가 잘못 같은 폴더로 뭉쳐 보이는 걸 막는다. **탭은 경로 사전순으로 렌더**된다(플레인 문자열 비교, 로케일 무관) — `tabs.tabs`의 저장 순서 자체는 무변경(렌더용 정렬 사본일 뿐, 선택/닫기는 여전히 tabId로 원본을 참조), 화살표 키 로빙도 이 정렬된 표시 순서를 따른다. **접힌 볼트의 찬 폴더 글리프** — 접혔는데 탭이 1개 이상이면(`has-tabs`) 닫힌 폴더 아이콘이 `currentColor` 22% 틴트로 옅게 채워져 "안에 뭔가 있다"를 알리고, 탭 0개는 빈 윤곽선 그대로 남는다.
- **볼트별 탭** — `VaultTabStore`가 탭 경로와 활성 탭을 저장한다. 현재 편집기는 하나를 재사용하며, 전환·닫기·watcher 교체는 복구 확인 후 커밋되는 단일-editor/단일-active-watcher 경계다. 탭마다 독립적인 살아있는 CodeMirror 인스턴스가 있다고 주장하지 않는다.

### 3.1 인라인 요소
- **강조** — bold(`**`), italic(`*`), code(`` ` ``), strikethrough(`~~`) — **테이블 셀 안에서도 렌더**(inline-render.ts).
- **CJK 인접 플랭킹 완화** — 한국어 조사 등 CJK 글자가 강조 마커에 바로 붙을 때(`**"New Policy"**를`, `**…(\`user_id\`)**와`, `*"동물-되기와 …"*라`, `***"강조"***를`) CommonMark 표준 플랭킹 판정으로는 실패하던 `**` 볼드·`*` 이탤릭·`***` 볼드이탤릭을 성립시킨다. CJK 인접에서만 적용하는 의도적 CommonMark 표준 이탈(`**`·`*`·`***` 대상, 길이 4 이상 delimiter run과 `_`/`__`는 비대상 — 근거: `_workspace/01_architect_design.md` §4, `***` 확장은 `_workspace/02_frontend_changes.md` "재호출 2차" 실측). **중첩 지원** — 이탤릭 바깥/볼드 안쪽(`*"a **b**"*`)과 볼드 바깥/이탤릭 안쪽(`**"a *b*"**`) 모두, 구제한 강조가 파서가 만든 안쪽 노드를 감싸는 형태로 정상 렌더(mark decoration 겹침 허용 + conceal 구간이 서로소). `***` 구제는 같은 구간에 `cm-em`과 `cm-strong`을 동시에 얹는다. 라이브프리뷰 데코 레이어(`live-preview/features/cjk-emphasis.ts`)에서만 동작 — outline/read-mode 렌더러(`inline-render.ts`)는 미반영(별도 정규식 렌더러라 스코프 밖).
- **하이라이트** — `==mark==`(GFM 확장).
- **링크 / 위키링크** — `[text](url)`, `[[target]]`(피커·자동완성·active/missing/asset). **위키링크 열기 = 현재 창 안전 트랜잭션** (single-window-opening, 신규) — 존재하는 타겟 클릭은 `requestDocumentOpen({kind:"resolved-document"})` → `openDocumentSafely`로 **현재 창**에서 열린다(과거의 `open_path` 새 창 호출은 폐기됨); 실패 시 `openDocumentSafely`의 복구 모달이 뜬다. 위키링크에는 ⌘/Ctrl 새 창 변형이 없다 — 새 창은 탐색기·파일 찾기의 명시적 제스처 전용(1.2 "명시적 새 창 열기" 참고). **`.txt` 타겟** — `[[note.txt]]`는 `[[note.md]]`와 같은 방식으로 열린다(없으면 `create_markdown_file`로 자동 생성 — md와 동일 취급). 단, 확장자 없는 타겟(`[[note]]`)의 기본 확장자는 여전히 `.md`다(`.txt`로 바뀌지 않음 — 기존 볼트 링크 보존). **표준 마크다운 링크 `[text](./note.md)`(신규, single-window-opening)** — **영구 볼트의 문서에서만** 동작한다(글로벌 볼트·볼트 컨텍스트 없음은 `no-vault-context`로 거부). 링크가 리터럴 상대 `.md`/`.txt` 경로이고, 퍼센트 인코딩이 정확히 한 번만 디코드되며, 절대/드라이브/UNC/알 수 없는 스킴/쿼리스트링/역슬래시 혼용이 아니고, 심볼릭 링크 해석(`canonicalize_path`) 후에도 문서·타겟 둘 다 그 볼트 루트 안에 남는 일반 파일일 때만 위키링크와 같은 현재-창 안전 트랜잭션으로 열린다(`local-doc-link.ts`). **위키링크와 달리 존재하지 않는 대상을 자동 생성하지 않는다** — 실패 시 링크에 한국어 사유(`LOCAL_LINK_REJECTION_MESSAGES`)가 표시된다. 표/릴리스노트처럼 문서 컨텍스트가 없는 렌더러와 글로벌 볼트에서는 이 기능 전체가 비활성. **자동 URL 감지(autolink)** — 맨손 `https://…`/`www.…`/이메일과 `<https://…>` 모두 클릭 가능한 링크로 렌더(GFM Autolink는 기존에 이미 파싱되고 있었고, 이번에 `features/autolink.ts`가 렌더·클릭을 얹었다). **`[[https://…]]`/`[[https://…|별칭]]`(위키링크 외부 URL)** — 파일 해석(`wikilinkPath`)·`path_exists`·`create_markdown_file`을 전혀 타지 않고 바로 외부로 연다(옵시디언 습관으로 URL을 위키링크에 붙였을 때 쓰레기 파일이 생기던 결함 제거). **외부 열기 단일 출구** — 마크다운 링크/위키링크/autolink/표 셀·설정판 링크 넷이 `open-external.ts`의 `isExternalUrl`(화이트리스트: `http(s)/mailto/tel`)+`openExternal` 하나를 공유(실패 시 조용한 무반응 대신 에러 표식+title). **표 셀 링크** — 표 안 `[text](url)`/맨손 URL도 이제 렌더·클릭된다(`inline-render.ts`의 `matchLinkToken`); 표 안 `[[wikilink]]`/상대경로는 링크 스타일로 보이되 클릭은 기존처럼 블록 진입(원문 노출)으로 폴스루(스코프 밖, 후속 과제).

- **줌** — ⌘ +/−/0(본문 스케일). 최대 **300%**(`FONT_SCALE_MAX`, `settings/app.ts` — 4K에서 200%가 부족하다는 리포트로 상향). `--font-scale`을 곱하는 곳은 `.cm-line`류와 `.viewer-panel`뿐이라 300%에서도 툴바·상태바(고정 px)와 겹침 없음.
- **괄호 자동 닫기** — `[`→`[]`, `[[`→`[[]]`.
- **마크업 래핑** — 선택 위 `=`(==highlight==), `*`(italic→bold→both).
- **붙여넣기 링크화** — 선택 + URL paste → `[선택](URL)`.
- **위키링크 자동완성** — `[[` 입력 시 파일 피커. `.md`·`.txt` 둘 다 후보로 뜨고, `.txt` 항목은 확장자를 포함해 삽입된다(`plain.txt` 선택 시 `[[plain.txt]]` — `.md` 항목의 "확장자 뗀 stem 삽입"과 다른 규칙: stem을 넣으면 `[[plain]]`이 되어 기본 확장자 규칙상 `plain.md`라는 다른 파일을 가리키게 되므로).
- **문서 내 찾기·바꾸기** (`search.document`=⌘F, `search.replace`=⌥⌘F) — `@codemirror/search`의 기본 패널을 그대로 씀(자체 find UI는 판정 기각 — 콜드로드 이득 없이 유지비만 증가, `_workspace/01_architect_design.md` 판정1). `find.ts`가 얹는 것: ① `EditorState.phrases`(패널이 실제로 읽는 상태-facet SSOT) 경유 한국어 11키 문구(찾기/바꾸기/다음/이전/모두/대소문자 구분/단어 단위/정규식/닫기 등) — `search()` 자체엔 i18n 옵션이 없어 이 경로가 유일. ② `searchKeymap`에서 `Mod-f` 바인딩만 제거한 `FIND_KEYMAP_WITHOUT_MOD_F`(F3/⌘G 다음매치·Esc 닫기 등 패널 내부 chord는 그대로) — ⌘F 소유권은 전역 단축키 디스패처(`search.document` 액션, 항상 CM keymap보다 먼저 캡처)가 갖고, `openFindPanel`을 호출해 여는 단일 경로로 수렴. 패널 자체는 `state.readOnly`를 보고 바꾸기 행/버튼을 자동 생략하는데, **mermark의 기본 모드가 리더**(`modeSetting` 기본값, `settings/app.ts`)라 별도 처리 없이는 바꾸기가 기본 상태에서 아예 도달 불가능했다(v0.9.12 실앱 결함). 그래서 **`search.replace`(기본 ⌥⌘F, `main.ts`의 `openReplacePanel`)** 가 리더 모드면 `modeSetting`을 `"edit"`으로 전환(기존 SSOT 경로 재사용, 직접 상태 조작 없음)한 뒤 같은 패널을 연다 — 그러면 패널이 진짜 바꾸기 행을 그린다. ⌘F(`search.document`)는 리더에서도 그대로 찾기만 열되, 바꾸기 행이 없을 땐 패널 DOM에 **"바꾸기 (⌥⌘F)" 버튼**(`find.ts`의 `syncReplaceHint`)을 얹어 경로를 보여준다 — 라벨은 `effectiveBinding("search.replace")`를 읽어 표시하므로 재바인딩해도 안내 문구가 틀어지지 않고, 편집 모드로 넘어가 진짜 바꾸기 행이 뜨면 힌트는 자동 제거(중복 노출 없음). 검색 패널 CSS는 캔버스 표면 토큰(`--bg/--fg/--border/--accent/--muted`)만 쓴다 — 라이트·클로드 테마는 사이드바가 반전(어두운) 팔레트라 `--sidebar-*` 폴백을 쓰면 입력창이 검정 위 검정이 됐다(v0.9.12 실앱 결함, `styles.css` `.cm-panel.cm-search`). **뷰어(pdf/docx/hwp 등)가 열려 있으면 두 액션 모두 no-op**(에디터가 화면에 없는데 뒤에서 패널이 뜨는 혼란 방지) — ⌘⇧F(파일 찾기)는 뷰어 열림과 무관, 결과를 열면 `openInWindow`가 뷰어를 닫아준다.
- **리스트 Tab/Shift-Tab 들여쓰기** — 커서가 리스트 항목(불릿·숫자)에 있을 때 Tab=한 단계 중첩(4-space)·Shift-Tab=해제(`list-indent.ts` 리스트 인식 커스텀 핸들러 — `indentMore`/`indentLess` 위임). 리스트 밖 Tab은 기존 동작(포커스 이동) 보존. `[[` 완성 팝업 열림 시 Tab=완성 수락(indent 아님). `indentUnit` 4-space(ordered 리스트 중첩 성립).

### 4.3 네비게이션
- **풋노트 양방향** — 참조↔정의 클릭 이동 + ⌘hover 정의 프리뷰(forward 비동기 위젯 재center).
- **위키링크 이동** — 대상 열기(현재 창의 안전 트랜잭션, 위 3.1 "링크 / 위키링크" 참고), Alt=원문 편집. **`[[#헤딩]]`(앞 `#`, 파일부 없음)은 현재 문서 내 헤딩으로 이동**(옵시디언식 — `sameFileHeadingAnchor` 판정 → `findHeadingByText`로 collectHeadings 매칭(대소문자·마커 무시) → `jumpTo` 랜딩, 파일 열기 아님·IPC 0). 없는 헤딩은 graceful no-op. `[[#^block]]`(블록 참조)·`[[file#헤딩]]`(크로스파일)은 현행 유지(범위 밖).
- **경로 열기** — 푸터 왼쪽 버튼 → 인라인 경로 입력 → 현재 창에 문서 전환(vim `:e` 감). 입력한 경로를 **등록된 뷰어가 claim하면 그 뷰어로 열린다**(`viewerForEntry` 게이트 → `openWithViewer`) — 탐색기·파일 찾기가 이미 적용하던 것과 같은 분기다. 2026-08-17 이전엔 이 진입점만 레지스트리를 무시하고 무조건 `openDocument`로 보내, PDF 경로를 입력하면 `stream did not contain valid UTF-8`로 실패했다(같은 파일을 탐색기에서 클릭하면 정상 열림). 뷰어는 문서를 대체하지 않고 뷰어 슬롯을 점유하므로 이 분기엔 미저장 가드가 없다 — 그건 `openDocument`의 몫이고 이 갈래는 거기 닿지 않는다.
- **목차보기 (Outline/TOC)** — 상태바 버튼 토글 → **좌측 사이드바**(`.outline-aside`, 탐색기와 같은 사이드바 셸). 헤딩 위계 트리, 항목 클릭 시 해당 헤딩으로 이동(footnote와 공유하는 `jumpTo` 랜딩). 문서 변경 시 디바운스 실시간 갱신. 인라인 마크 정규화(`**B**`→`B`, 링크/위키링크는 표시 텍스트). **탐색기와 상호배타**(좌측 사이드바는 한 번에 하나 — 목차 열면 탐색기 닫힘, `closeOtherSidebars` 단일 코디네이터). 사이드바는 에디터 측정 트리 밖(줌 가드). **비마크다운 뷰어 override 소스** (신규, EPUB 뷰어) — `OutlinePanel.setOverride(items | null)` 한 자리로, EPUB 뷰어가 열려 있는 동안은 md 헤딩 대신 그 책의 EPUB3 nav/EPUB2 NCX 목차를 보여주고(항목 클릭 → 해당 챕터로 스크롤), 뷰어가 닫히면(Esc/✕ 포함) 자동으로 md 헤딩 경로로 복원된다 — 별도 사이드바 패널을 새로 만들지 않고 기존 목차 자리를 재사용(패널 신설의 라이프사이클/상호배타 분기 회피).
- **문서 네비게이션 히스토리 (Back/Forward)** — `⌘[` 이전 문서 / `⌘]` 다음 문서. 브라우저식 선형 back/forward 스택(`src/history/nav-history.ts` 순수, 세션 한정 in-memory·비영속). `openInWindow` 단일 지점에서 방문 기록(back/forward 이동은 포인터만 이동 — 재기록 안 함, 무한루프 차단). 최근문서(MRU 목록)와 **별개 개념**(히스토리 = 방문 스택+포인터). 빈 스택 no-op, 삭제된 경로 graceful(스킵+prune), 상한 50. *알려진 트레이드오프: CodeMirror 기본 `⌘[`/`⌘]`(indent)는 전역 디스패처가 우선.*
- **최근 문서 (Recent Documents)** — 상태바 탐색기 다음 버튼 토글 → **좌측 사이드바**(`.recent-aside`, 탐색기·목차와 같은 `.sidebar-aside` 셸 공유 — 공유 폭 sash·토글 아이콘 스왑·상호배타). 최근 연 문서 목록, 항목(basename + **좌측 생략 경로** `<bdi>`+`direction:rtl` — 즐겨찾기와 동일 패턴, 뒤쪽 폴더명/파일명 노출) 클릭 → 현재 창 열기(`openInWindow` 재사용). 최근순·중복제거·상한 15, **재시작 후 유지**(localStorage). 없는 경로 클릭은 graceful(에러 표시 + 목록에서 제거). **탐색기·목차와 3-way 상호배타**(좌측 사이드바는 한 번에 하나 — `closeOtherSidebars` 단일 코디네이터).
- **폴더 즐겨찾기 (Favorite Folders)** (M4 도입 → **M5 재구조화**) — 별도 사이드바 뷰가 아니라 **탐색기 사이드바 하단 분리 섹션**(`.explorer-favorites` `<section>`, 상=파일 트리 `flex:1` / 하=즐겨찾기 `max-height:40vh`+자체 스크롤 — 트리와 **동시 상시 노출**). 사용자가 큐레이션하는 폴더 핀 목록. **추가/해제 = 탐색기 트리 폴더 행 우측 별 토글**(`.explorer-star`, 3-state: 평소 흐림 → hover 진함 → favorited 채워진 별 `--accent` 상시 우선; 파일·`..` 무별). 별 클릭은 `toggleFocusedFolderFavorite`로 `favoriteFoldersSetting` 토글(폴더 열기와 무충돌 — 위임 click에서 `findStarButton` early-return, 키보드 **Space** WCAG 2.1.1, `tabindex=-1`·`aria-pressed`로 roving tabindex 불변식 무손상). 항목(basename + **좌측 생략 경로** `<bdi>`+`direction:rtl` — 뒤쪽 폴더명 노출) **클릭 → `explorer.jumpToRoot(abs)`**(M3 재사용), 항목별 **X 제거**. **최근문서(MRU)와 별개 도메인**: 즐겨찾기 = 추가 순서 유지·중복제거·**cap 없음·자동 prune 없음**(외장/언마운트 폴더 큐레이션 보호 — `src/favorites/favorite-folders.ts` 순수 `pushFavorite`/`removeFavorite`/`isFavorite`/`reorderFavorite`). **드래그 앤 드롭 순서 변경**: 항목을 pointer 드래그로 재정렬(4px 임계로 클릭과 구분 — 드래그 아니면 기존 jump/별/X 그대로, sash식 DRAG=프리뷰/RELEASE=커밋, `pickDropIndex`+`dropIndexToFinalIndex` 순수 계산으로 하향 드롭 인덱스 시프트 보정), 키보드 대체 **Alt+↑/↓**(포커스 복원). 순서는 `favoriteFoldersSetting`에 즉시 영속(main 단일 writer). SSOT `favoriteFoldersSetting`(`string[]` localStorage, **재시작 유지**) **단일 subscribe sink가 두 뷰(하단 섹션 + 트리 별) 동시 갱신**(손 fan-out 0). **⌘⇧B**(`favorites.toggle`) = 탐색기 열고 즐겨찾기 섹션으로 스크롤·포커스(`revealFavorites`→주입된 `focusFavorites`, 별도 상단 토글 버튼 없음). 섹션·별은 에디터 측정 트리 밖(줌 가드), 테마 var만. 신규 IPC command 0(frontend 단독).
- **파일 찾기 (Find Files)** (`search.files`, `⌘⇧F`) — VS Code `⌘P`식 quick-open. **좌측 사이드바**(탐색기·최근·목차와 같은 셸, 상호배타·`registerSidebarPanel` 4번째 등록으로 상단 토글 줄에 검색 아이콘 자동 합류) + 별도 상단 토글 버튼. 패널을 열 때 현재 탐색기 루트(없으면 baseDir) 아래를 `list_files_recursive`로 **1회만** 스캔해 메모리 캐시(`cachedFiles`)에 담고, 이후 타이핑마다는 그 캐시 위에서 **순수 클라이언트 퍼지 매칭**만 재계산(`fuzzy.ts`의 `rankHits`, 상한 `MAX_RESULTS`) — 키 입력당 IPC 호출 0. 스캔이 `truncated:true`(백엔드 상한 도달)면 "폴더가 너무 커서 일부 파일은 스캔되지 않았습니다" 배너로 잘렸음을 정직하게 신고(표시 상한이 아니라 스캔 자체가 중단됐다는 사실). 결과 행: `.md`·`.txt`는 항상 열림, 그 외는 뷰어 등록 여부(`canOpenWithViewer`)로 openable/`.is-nonmd` 갈림 — 탐색기와 동일 규칙 공유(`file-icons.ts`의 `isEditableTextFile` SSOT). **키보드 완결**: ↑↓ 이동·Enter 열기(현재 창, `openInWindow`+`commitBeforeSwitch` 재사용)·⌘Enter 새 창(`open_path`)·Esc 닫기, IME 조합 중 Enter는 조합 확정으로만 처리(행 활성화 안 함). 하이라이트는 매치 위치를 `<mark>`로 스플라이스. 에디터 측정 트리 밖(줌 가드, 데코 0개) — live-preview 파이프라인과 무관.
- **파일 탐색기 (File Explorer)** — 상태바 좌 네비 버튼 또는 **⌘B**로 토글하는 **좌측 사이드바**(`.workspace` flex row: aside ∣ 에디터, 상태바는 폭 전체). 현 문서 폴더 루트의 **레이지 트리**. 폴더 **클릭 시에만** 자식을 `list_dir`로 읽어 펼침(경로별 캐시, 재펼침 재호출 없음) — **hover로는 아무 것도 안 열림**(WCAG 1.4.13). 최상단 `..` **단일클릭/Enter → 상향**(부모가 새 루트, 캐시 clear+재구축). **WAI-ARIA Tree 키보드**: ↑↓(포커스 이동) →(닫힌폴더 열기/열린폴더 첫자식) ←(열린폴더 닫기/부모) Enter(활성화) Home/End, roving tabindex(트리 전체 tab stop 1개). **포커스≠선택 분리**: 화살표는 포커스 링만 이동, Enter/클릭만 파일 활성화(단일선택). 파일 클릭/Enter → **현재 창 열기**(main의 `openInWindow`+`commitBeforeSwitch` 재사용, `activateItem` 단일 경로). **에디터로 여는 확장자는 `.md`·`.txt`뿐**(`file-icons.ts`의 `isEditableTextFile` SSOT — `.txt`는 에디터 안에서 `.md`와 완전히 동일하게 렌더된다, 플레인텍스트 모드 분기 없음); `.markdown`/`.mdx`를 포함한 그 외 파일은 회색(`.is-nonmd`)+no-op(뷰어가 등록돼 있으면 예외). **폴더/파일 아이콘**: 폴더는 무변경 — `--sidebar-accent` 틴트 + 열림/닫힘 글리프 스왑(`folder`↔`folder-open`, `aria-expanded` 동기, Lucide). 파일은 **Material Icon Theme**(MIT, `scripts/generate-material-icons.mjs`/`npm run - **상태바 (footer)** — 하단 = **브레드크럼(좌, 풀폭) + 본문 너비 슬라이더 + 커서/위치 + 저장 상태 인디케이터(우)**(저장됨/저장중/충돌, 수동 저장·리로드 버튼 없음). 토글·모드·테마·설정은 상단 타이틀바. `arrangeStatusBar` 단일 계약(순서: breadcrumb·spacer·width·save·pos).
- **본문 너비 슬라이더 (footer)** — `readingWidthSetting`(설정 › 타이포그래피 › 본문 너비와 동일 SSOT, `--measure` 구동)을 즉시 조절하는 푸터 미니 슬라이더(`makeWidthSlider`). 창(에디터) 폭의 %(40–100%, 기본 68%) 기반 — 어떤 모니터·해상도에서도 창 상대로 동일하게 동작하고, 최대 100%는 창을 꽉 채운다. `.cm-content`가 `max-width: var(--measure)`로 직접 소비하며, ⌘±(`--font-scale`) 폰트 줌과는 분리(줌은 글자만 키우고 컬럼 폭은 창의 고정 비율 유지). 드래그 시 `input` 이벤트로 setting에 바로 반영, 다른 writer(설정 패널)가 값을 바꾸면 thumb도 재반영(양방향 bind). bounds는 `READING_WIDTH_MIN/MAX_PCT` 공유 상수로 설정 패널과 드리프트 없음. 측정 트리 밖(줌 가드 준수). **마이그레이션**: 기존 글자수(ch)시대 저장값(40–90)은 그대로 %(40–90%)로 재해석돼 유효 범위에 자연 안착하고, px시대의 큰 저장값(예: 820)은 100%로 클램프된다 — 별도 버전 플래그나 변환 로직 없이 `clampReadingWidth`(40–100 범위)가 두 시대 값 모두를 monotonic하게 흡수.
- **자동 업데이트 확인 + 푸터 업데이트 버튼** — 부팅 시 지연 실행되는 조용한 자동 확인(`main.ts`의 `boot()`, `setTimeout(() => ensureCheckedOnce())` — 콜드 로드·첫 페인트 0 영향, 네트워크 실패는 조용히 무시)과 푸터 업데이트 버튼(`makeUpdateButton`, `chrome/status-bar/update.ts`)이 `src/update/update-flow.ts`(단일 상태머신 SSOT: idle→checking→found→downloading→downloaded→installing)를 공유한다. 평소 숨김 → 업데이트 발견 시 `v{버전} 업데이트` 버튼이 accent 톤으로 노출, 클릭 시 다운로드 진행률 캡션 → 설치·재시작. **다운로드가 끝나면 자동으로 설치·재시작한다**(2026-08-19, 이전엔 사용자가 "설치하고 재시작"을 눌러야 했다). 자동 재시작 직전에 `commitBeforeSwitch()`로 **대기 중인 저장을 먼저 확정**하고, 그게 실패하면(충돌 등) 재시작하지 않고 멈춘다 — 재시작을 강행해 편집을 버리는 경로는 없다. 자동 설치는 **다운로드 1회당 1회**만 시도한다(`autoInstallArmed`, `"downloading"` 진입 시 재무장): `installAndRelaunch`가 실패하면 phase를 `"downloaded"`로 되돌리는데, 그 되돌림이 자동 설치를 다시 부르면 실패-재시도 무한 루프가 된다. 자동 시도가 실패한 뒤에는 기존 "설치하고 재시작" 버튼(상태바·설정 패널 양쪽)이 수동 폴백으로 그대로 살아 있다. 트리거는 `main.ts`의 `subscribeUpdate` 구독 한 곳이라 어느 sink에서 다운로드를 시작했든 동일하게 동작하고, `update-flow.ts`는 여전히 에디터를 모른다(의존 방향 유지 — 저장 확정은 에디터를 아는 `main.ts`만 할 수 있으므로 트리거가 거기 있다). 상태바에서는 **버튼이 상태를, 캡션이 숫자를** 담당한다(`downloadStat`는 상태어 없는 진행 수치, `formatDownloadProgress`는 그 위에 접두어를 붙인 값 — 한 값에서 파생되어 두 표시가 어긋날 수 없다). 이전엔 둘 다 "다운로드 중..."을 말해 `다운로드 중...  다운로드 중... 53% (...)`로 중복 표시됐다(사용자 리포트 2026-08-19). 설정 › 버전 패널도 같은 모듈을 경유(`checkNow`/`startDownload`/`installAndRelaunch`)해 중복 로직 없이 1클릭 설치 UX를 유지하고, 부팅 자동 확인이 이미 찾은 업데이트가 있으면 패널을 열 때 "업데이트 확인" 클릭 없이 카드가 즉시 렌더된다. 신규 Tauri IPC 0(기존 `plugin-updater`/`plugin-process` 재사용), 브라우저 mock은 무변경(기존에 `check`를 이미 null로 강등).
- **브레드크럼 푸터 + 조상 점프** (M3) — 푸터 좌측이 현재 탐색기 루트 경로를 세그먼트로 표시(`breadcrumbSegments` 순수 함수 — 홈 `~` 축약 label ↔ 실경로 abs 분리, posix `/`·windows 드라이브 루트 노드 선두). **각 세그먼트 클릭 = 그 조상 폴더로 루트 점프**(`explorer.jumpToRoot(abs)` — 닫힌 패널이면 `revealShell`로 열고 점프, `changeRoot` 재사용). 브레드크럼 SSOT=explorer 루트(`onRootChange` 관찰, `renderTree` 정규화 직후 단일 지점). 탐색기 aside 헤더는 정적 "탐색기"로 되돌리고(경로 표시 단일 출처화), 전체경로 title/aria는 브레드크럼이 승계. 긴 경로 overflow-x. 측정트리 밖(줌 가드), 테마 var만.

5분기 컬럼 어피니티 알고리즘은 의도적으로 안 씀 — 그 알고리즘의 "그 외엔 NUMERIC" 기본값이 `BOOLEAN`/`DATE` 같은 무-타입 컬럼까지 숫자로 우측정렬해버리는 오분류를 만든다)로 먼저 판정하고, 빈 타입(무-타입 컬럼)일 때만 첫 페이지 샘플에 `looksNumeric`(`src/text/numeric-cell.ts`, 엑셀 뷰어와 공유) 다수결로 폴백 — 한 번 계산해 전 페이지에 재사용하므로 스크롤 중 정렬이 바뀌지 않는다. 빈 테이블(`rowCount === 0`)은 뷰든 테이블이든 동일 경로로 "행 없음"만 표시하고 `sqlite_rows`를 아예 호출하지 않는다. 어떤 invoke든 실패하면(손상·락 DB 등) 패널에 사람이 읽을 에러 문구를 보여줄 뿐 뷰어를 자동으로 닫지 않는다(엑셀/HWP와 같은 catch 관례). `.sqlite-viewer-table`은 엑셀 뷰어의 리포트 스타일(세로 격자선 없이 가로줄만, 짝수행 얼룩말, sticky 헤더, `--viewer-zoom` 소비로 헤더 `[−][+]`가 표 텍스트에 먹음)을 `styles.css`에 **직접** 선언해 공유한다(엑셀 확장 내부를 import하지 않음 — chrome→extensions 역방향 금지, api-fence 정신과 동일). 신규 CSP/capabilities 변경 없음.
- **EPUB 뷰어 (내장, spine 연속 스크롤 + 목차)** — `src/chrome/viewer/epub-viewer.ts`, HWP/SQLite와 같은 **내장** 경로로 `registerViewer({ id: "epub", extensions: ["epub"] })`(백엔드 커맨드 2건 신규 — `arm_epub_view`/`read_epub_entry` — 라 R11의 "확장은 신규 IPC 0" 계약을 벗어난다). **`.epub` 파일 자체가 armed root**(임시 해제 없음) — `arm_epub_view(path)`가 zip 시그니처를 확인해 토큰을 발급하고, 요청마다 백엔드가 zip 아카이브를 열어 해당 엔트리 바이트만 읽어 `epub://<token>/<entry>` 커스텀 스킴으로 응답한다(containment은 zip 엔트리 정확 일치 조회가 구조적으로 보장 — fs join이 없어 traversal이 성립하지 않는다). **책의 raw HTML은 앱 DOM에 절대 들어가지 않는다** — 앱이 파싱하는 것은 메타데이터 XML(container.xml/OPF/nav/NCX/encryption.xml, `read_epub_entry` + `epub-parse.ts`의 `DOMParser` 전용 순수 함수)뿐이고, 챕터 본문은 **챕터당 iframe 1개**가 `epub://` 스킴으로 직접 로드한다(CSS 오염 방지 + 앱-교차 오리진 XSS 표면 원천 차단). 챕터 iframe의 `sandbox`는 정확히 `"allow-scripts allow-same-origin"`(WebKit 커스텀스킴 `canDisplay` 게이트로 형제 CSS/이미지/폰트 로드에 allow-same-origin 필요) — 책 **스크립트는 sandbox가 아니라 CSP 층**에서 죽는다(백엔드의 per-token CSP가 `script-src`에 자체 임베드 자산 `measure.js` 한 URL만 명명, 원격 `https:` 전부 부재). **연속 스크롤**은 spine 순서로 쌓인 챕터 플레이스홀더(`min-height: 60vh`)를 IntersectionObserver로 근접 챕터만 `iframe.src` lazy 세팅(hwp 뷰어의 `observePages` 패턴 재사용, jsdom 폴백 = 즉시 전부)하고, 프레임 안에서 도는 유일한 코드인 `measure.js`(ResizeObserver + `id`별 `offsetTop` 맵)가 `postMessage`로 높이/앵커를 보고하면 부모가 origin+source 이중 검증(`chapterIndexForMessage`, 위조 메시지 무시) 후 해당 챕터 높이를 갱신한다 — 줌 변경도 이 경로로 "공짜로" 흡수(iframe 폭이 바뀌면 프레임이 재측정해 새 높이를 다시 보고). **목차**는 별도 사이드바 패널 없이 기존 목차 패널의 override 소스(위 항목)로 표시되며, EPUB3 nav vs EPUB2 NCX 판별은 `epubTocSource` 단일 함수(nav 우선, 없으면 `spine[toc]`→NCX)에 갇혀 있다. **DRM 판정**: encryption.xml이 폰트 난독화 알고리즘 2종(IDPF/Adobe embedding)만 가지면 정상 열람(오거절 방지), 그 외 콘텐츠 암호화가 있으면 사람이 읽을 거절 문구로 막는다(`hasContentEncryption`/`epubOpenErrorMessage`). **고정 레이아웃(만화 등)은 거절하지 않고 최선 노력 렌더**(챕터=이미지 1장 xhtml이 세로로 자연히 쌓임). 뷰어 로컬 줌은 html 뷰어의 `transform` 트릭을 챕터별로 적용(`shell.zoom`, `⌘±`와 완전 분리), 레이아웃은 2026-07-27 평면 규약(페이지 액자/그림자 없음, 흰 배경만 챕터 경계 신호). **알려진 한계**: 브라우저 dev(`epub://` 스킴 없음)는 mock이 명확 거절만 반환 — 실앱(`tauri build`) 전용 검증 대상. 책 내부 검색은 범위 밖. **읽던 위치 기억 (자동, v2)** — 다시 열면 조용히 마지막 읽던 자리로 간다(배너·버튼 없음, UI 추가 0). 키는 OPF `dc:identifier`(있으면 파일 이동/개명에도 유지되고 같은 책의 다른 사본과 위치를 공유) 우선, 없으면 절대경로 폴백(`epubPositionKey`). 위치는 챕터 spine entry + 챕터 내 `ratio`(무차원, 줌/창크기 무관) + 직전 `[id]` 앵커(measure.js가 이미 보고하는 `anchors` 맵 재사용 — measure.js 코드 변경 0)를 병기하고, 복원 시 앵커를 우선한다. 저장은 스크롤 trailing 디바운스(~800ms) + `shell.onTeardown` 즉시 플러시. **복원은 절대 스크롤값을 맞추지 않는다** — 저장된 챕터를 IntersectionObserver 없이 즉시 강제 로드 → 코스 조준 1회 → 이후 도착하는 모든 `measure.js` 메시지(대상 챕터 자신 + 이웃 챕터의 높이 교정 전부)마다 현재 레이아웃 기준으로 재조준하는 수렴 루프이며, 종료 조건은 3중이다 — 사용자 입력(`wheel`/`pointerdown`/`keydown`, `scroll` 자체는 프로그램 스크롤도 쏘므로 신호로 안 씀) 즉시 종료, 대상 챕터의 첫 measure 이후 추가 measure 없이 `RESTORE_QUIET_MS`(~600ms) 경과(수렴 판정), 안전망 `RESTORE_HARD_TIMEOUT_MS`(~10s). 복원 진행 중에는 저장을 게이트(추정치가 좋은 저장값을 덮어쓰는 사고 방지, teardown 플러시도 동일 게이트 — 게이트 체크가 게이트를 지우는 `endRestore()`보다 반드시 먼저 실행되도록 한 콜백에 합쳐 순서를 고정). 목차 점프는 진행 중이던 복원을 즉시 취소한다. 시작점 근처(첫 챕터·ratio<ε·앵커 없음)는 애초에 복원 시도조차 하지 않는다(`shouldRestorePosition`). 저장 entry가 현재 spine에 없으면(식별자 충돌) 복원하지 않는다. 저장소는 `recentDocsSetting`/`favoriteFoldersSetting`과 같은 SSOT-only `defineSetting`(`epubPositionsSetting`, `mermark.epubPositions`, JSON 맵) — 신규 IPC 0, 새 저장 메커니즘 0. LRU 100권 캡(`upsertPosition`). 끄는 설정 없음(recentDocs와 동일한 판단 — 해가 없고 벗어날 길이 이미 자연스럽다). PDF/HWP/docx로 일반화하지 않음(뷰어마다 위치 모델이 다름 — 두 번째 위치-기억 뷰어가 실제로 필요해지면 그때 공용 추출).
- **웰컴 대시보드** — 파일 인자 없이 실행 시 에디터 대신 표시(`src/welcome/welcome-pane.ts`의 `createWelcomePane`, 주입식 — main.ts 인라인에서 모듈 추출). 즐겨찾기·최근 문서 카드 그리드 + **빈 상태 CTA**: 둘 다 비어 있으면(`isBlankSlate` 순수 판정 → `reflectBlankSlate`가 `is-blank-slate` 토글, 두 구독 콜백+마운트 3곳에서 idempotent 호출) 즐겨찾기·최근 섹션을 접고 **워드마크 + "폴더 열기" 버튼 + 단축키 힌트만의 단일 히어로**로, 하나라도 항목이 생기면 카드 그리드로 복귀. CTA는 기존 explorer 열기 재사용(신규 IPC 0) + 힌트 ⌘B(`effectiveBinding` 파생이라 사용자 재바인딩 반영). 최근 문서 항목의 보조 경로 행은 **이름==경로일 때 생략**(`redundantPathLabel`(chrome/path-label.ts) — recent-panel·favorites-panel과 공유하는 단일 규칙).

## 범위와 후속 결정 (2026-08-11)

- **현재 제공** — workspace/vault 선택, vault별 파일 트리, 탭, 단일 active-editor/active-watcher 전환, 오류·삭제 복구는 위 L2와 L5에 기록된 현재 기능이다. 탭마다 독립적인 살아있는 에디터 인스턴스가 있다는 뜻은 아니다.
